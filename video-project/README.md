# Pool video: «حفرة في حوش بيتك ← مسبح»

This is a complete, procedurally generated 3D educational short (vertical 9:16, 1080×1920, 30 fps, H.264/AAC).
It is built in the style of the "How a … Becomes a …" reference videos and narrated by your own Arabic voiceover.

All 3D models, materials, animation, particles, sound effects and captions are generated by code in this
folder. There are no paid tools, no cloud rendering and no manual editing.

## Render it (Windows, Git Bash)

1. Copy this whole `video-project` folder to your PC. Put it on a drive with at least **10 GB free**.
2. Open **Git Bash** in the folder: right-click in the folder, choose *Open Git Bash here*.
3. Run:

```bash
bash render.sh
```

When it finishes, the video is at **`output/pool_final.mp4`**.

The first run downloads the missing tools into `tools/` and does this only once:

* **Blender 4.2 LTS** (portable, about 350 MB download). It is skipped if Blender 4.2 or newer is already installed in
  `C:\Program Files\Blender Foundation\…` or is on your PATH.
* **FFmpeg** (about 100 MB). It is skipped if `ffmpeg` is already on your PATH.

Nothing is installed system-wide. You don't need Python either: the helper scripts run inside Blender's bundled Python.

### Check it quickly first (recommended)

```bash
bash render.sh --preview
```

This renders half resolution, every second frame, with low samples, then upscales to 1080×1920.
The output is `output/pool_preview.mp4`. Use it to check timing, captions and sound before the long render.

## Options

| Command | What it does |
|---|---|
| `bash render.sh` | Full quality: EEVEE, 64 samples, 1080×1920 → `output/pool_final.mp4` |
| `bash render.sh --preview` | Fast check: 540×960, 15 rendered fps, 8 samples |
| `bash render.sh --quality medium` | Full resolution with fewer samples (faster) |
| `bash render.sh --quality cinematic` | Path-traced Cycles, 128 samples, denoised. Best look, much slower; a GPU is strongly advised |
| `bash render.sh --engine cycles` | Force Cycles for the chosen quality (GPU if found: OptiX → CUDA → HIP → oneAPI, else CPU) |
| `bash render.sh --device cpu` | Force Cycles to run on the CPU |
| `bash render.sh --encode-only` | Skip rendering. Re-mix the audio and re-encode the MP4 from the existing frames |
| `bash render.sh --rebuild` | Force a rebuild of the 3D scene |
| `bash render.sh --clean` | Delete the rendered frames of the chosen quality and start over |

**To change quality or resolution,** edit `"quality"` in `project-config.json`: `resolution`, `samples`, `engine`,
`crf` (lower means a bigger, better file) and `frame_step`. You can also add your own profile and call it with `--quality <name>`.

## Interrupting and resuming

You can stop with **Ctrl+C** at any time. Run the same command again and rendering continues at the first missing frame.
Each frame is written to a temporary file and renamed when it's complete, so a cut never leaves a broken frame.
If only the encode fails, use `--encode-only`; nothing is re-rendered.
If you change any scene code, `render.sh` rebuilds the scene and clears the stale frames on its own.

## Expected render time

The frame count is 2,400. These are rough estimates per frame at 1080×1920:

| Hardware | `full` (EEVEE) | `cinematic` (Cycles) |
|---|---|---|
| Recent NVIDIA/AMD GPU (RTX 3060 class) | 1–3 s → ~1–2 h | 10–25 s → ~7–16 h |
| Integrated GPU (Intel Iris / AMD APU) | 4–10 s → ~3–7 h | GPU path not recommended |
| CPU only (fallback to Cycles CPU) | n/a | 60 s+ per frame. Use `--preview` or `--quality medium` |

The render prints seconds per frame and an ETA as it goes. Frames take about 3–4 MB each (~9 GB for `full`).
Delete `output/frames_*` after you're happy with the MP4.

## What `render.sh` does

1. **System check:** OS, CPU threads, GPU name, free disk space.
2. **Dependencies:** `install.sh` finds or installs Blender and FFmpeg, then checks libx264 and numpy.
3. **Scene build:** `scenes/build_scene.py` generates the full scene and saves `build/pool.blend`. The scene has 774 objects: the villa courtyard, a soil block with
   geological layers that can be sliced into a cross-section, the pool shell, rebar, valve, skimmer, drain, jets,
   equipment pad with a see-through sand filter, a microscopic sand/bacteria set and a molecule set, 18 animated cameras and
   frame-exact particle emitters.
4. **Render:** `scenes/render_frames.py` renders PNG frames to `output/frames_<quality>/`, resuming where it stopped.
   If EEVEE can't start (no GPU/OpenGL), it falls back to Cycles on its own.
5. **Audio:** `scripts/mix_audio.py` lays 52 synthesised sound effects under the **unaltered voiceover**, timed to
   the on-screen actions. Effects duck slightly while the voice speaks. There is no music and no ambient bed.
6. **Encode and verify:** `scripts/assemble.py` overlays the Arabic captions, encodes H.264 High / yuv420p / AAC 48 kHz,
   normalises loudness to −14 LUFS (social media), then checks the codec, 1080×1920, 30 fps, pixel format,
   audio presence, that the duration is at least the voiceover length, and that a full decode has zero errors.

## Captions

* The text is your script, word for word, in Saudi dialect with its original punctuation.
* Arabic shaping (joined letters, lam-alef, tanween) is done with HarfBuzz, and words are laid out right-to-left.
  The captions are pre-rendered as images, so playback can never break the shaping, the way some subtitle renderers do.
* The spoken word is highlighted in yellow. Captions sit in the lower-middle safe area (bottom edge at 80 % of the height),
  clear of the TikTok/Reels UI.
* Timing comes from the voiceover: `align_captions.py` finds the real pauses in the audio and fits the script's
  phrases to them by expected speaking length. The 58 caption chunks follow the real phrasing. Word-level
  highlights inside a chunk are spread by letter count, which is accurate to within a fraction of a word.
* Want plain subtitles instead? `subtitles/captions_ar.srt` is included.

## Regenerating assets (optional)

You only need this if you change the script, the voiceover or the caption style. It requires Python 3.10+:

```bash
python -m pip install -r requirements.txt
python scripts/align_captions.py   # after replacing the voiceover or script
python scripts/make_captions.py    # after changing caption text/style
python scripts/make_sfx.py         # after tweaking sound effects
bash render.sh                     # the scene rebuilds automatically
```

## Troubleshooting

| Problem | Fix |
|---|---|
| `download failed` | Check your internet connection or proxy, then re-run. Downloads resume. Or install Blender 4.2+ / FFmpeg yourself and re-run. |
| Blender is installed somewhere unusual | `BLENDER="/d/Apps/Blender/blender.exe" bash render.sh` |
| FFmpeg is installed somewhere unusual | `FFMPEG="/d/ffmpeg/bin/ffmpeg.exe" bash render.sh` (ffprobe must be next to it) |
| `EEVEE render failed … falling back to Cycles` | Your GPU driver lacks OpenGL 4.3. Update the graphics driver, or accept Cycles (slower). |
| Out of GPU memory in Cycles | `bash render.sh --quality cinematic --device cpu`, or use `full` (EEVEE). |
| Disk full | Free space and re-run; finished frames are kept. Delete `output/frames_preview` once you've checked the preview. |
| `\r: command not found` | The `.sh` files got Windows line endings. Run `sed -i 's/\r$//' *.sh` once. (`.gitattributes` prevents this for git clones.) |
| Antivirus blocks `blender.exe` in `tools/` | Allow it, or install Blender normally from blender.org. |
| The encode failed but frames are fine | `bash render.sh --encode-only` |
| Want to look at the scene | Open `build/pool.blend` in Blender. Each shot's camera is bound to a timeline marker. |

## Notes on what was and was not tested

In the build environment, the scene was generated with Blender 4.2 (Python module). Test frames from all 18 shots were
rendered with Cycles at low resolution and inspected, and the audio mix, caption overlay, MP4 encode and
verification were run end to end. That included `render.sh` resuming a partial frame set and its EEVEE→Cycles fallback.
**The full-length, full-quality render has not been run.** That is meant to happen on your PC.
EEVEE could not be tested in the build environment because it has no GPU. If EEVEE output looks different from the
Cycles previews on your machine (for example, water transparency), `--quality cinematic` gives the reference look.
